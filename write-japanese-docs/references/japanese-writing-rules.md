# 日本語文書の執筆規範

## 情報の流れを作る

読み手が具体的な対象を思い浮かべてから、意味、条件、判断へ進めるように書く。

- 先に対象となる機能、変更、画面、事例、数値を示す
- 次に、その対象を判断するための概念や比較条件を説明する
- 説明のあとに、読者が行う操作または判断を示す
- 操作のあとに、結果を見分ける条件を置く

すべての文書を同じ順序へ固定しない。
結論を先に必要とする報告や判断依頼では、結論を置いてから根拠と条件を示す。

## 文の役割を区別する

文ごとに、事実、理由、判断、指示、例、補足のどれを担うか明らかにする。
異なる役割を一文へ詰め込まず、接続関係が分かる長さで分ける。

読者がその場で行う操作は、直接的な表現で書く。
目的、前提、状態、結果を説明する文まで、命令形へ変えない。

主語を省くと実行者、判断者、対象が曖昧になる場合は、主語を明記する。
「これ」「それ」「この対応」の参照先が複数ある場合は、対象名を書き直す。

## 文と段落の拍を変える

短文を増やすこと自体を目的にしない。
短い前提、理由や条件を扱う段落、操作や判断を固定する一文を組み合わせる。

同じ長さ、同じ構文、同じ役割の文が続く場合は、情報の関係を見直す。

1. 並列の条件や選択肢は、箇条書きまたは表にする
2. 一つの理由や因果を説明する内容は、段落にまとめる
3. 話題または読者の行動が変わる箇所で、段落を分ける
4. 節の役割が複数ある場合は、見出しを分ける

独立した短文は、結論、注意、判断条件、次の操作を固定するときに使う。
一文一行は強制せず、既存文書のMarkdown書式に合わせる。

## 読点を点検する

表、コード、引用を除き、一文に読点が3個以上ある場合は推敲対象とする。
読点の個数だけで違反とは判断しない。
複数の役割や長い列挙を一文へ詰め込んでいないか検出するための条件として使う。

推敲対象の文は、読点の役割に応じて次の順で確認する。

1. 三つ以上の同格要素を並べている場合は、意味を保った上位概念へまとめられないか確認する
2. 個々の要素を残して比較する必要がある場合は、表を使う
3. 個々の要素を手順、選択肢、確認項目として残す場合は、箇条書きを使う
4. 事実、理由、条件、結果のうち複数の役割を含む場合は、役割ごとに文を分ける
5. 文を分けると修飾関係や条件の範囲が曖昧になる場合は、読点を残す

たとえば「調査、計画、実装、検証、レビュー、引き継ぎを扱う」は、「調査から引き継ぎまでの工程を扱う」とまとめられる。
一方、設定値を複数の条件で比較する場合は、上位概念へまとめず表にする。

## 文同士の接続関係を示す

同じ段落で隣り合う文について、後の文が前の文とどのような関係にあるか確認する。

- 情報を追加する
- 前の内容と対比する
- 原則に例外を加える
- 理由または結果を示す
- 時間または手順の前後を示す
- 具体例を示す
- 前の内容を言い換える
- 前の内容から結論を導く

文頭の接続表現は、残すことを前提に点検しない。
接続表現を一度外して前後の文を読み、主語、述語、条件、時間表現だけで関係を一通りに読める場合は削除する。

接続表現を外すと関係が複数に読める場合も、先に主語、述語、条件を明記して関係を示せないか確認する。
接続表現は、関係そのものを示さないと誤読が生じ、文を書き換えると冗長または不明確になる場合だけ使う。
削除した接続表現を「これ」「それ」などの曖昧な指示語へ置き換えず、必要なら対象名を書く。

たとえば、共通資材とプロジェクト固有資材の管理場所を順に説明するだけなら、二文目を「一方」で始める必要はない。
それぞれの主語と管理場所を明記すれば、役割の違いを読めるためである。
「一方」は、同じ比較軸にある二つの対象の差が後続の判断に必要な場合に使う。

上の点検を行っても接続表現が必要な場合は、関係に応じて次の表現を候補にする。

| 関係 | 表現例 |
| --- | --- |
| 追加 | また、加えて |
| 対比 | 一方 |
| 例外 | ただし |
| 理由から結果 | そのため、したがって |
| 時間または手順 | まず、次に、その後 |
| 具体例 | たとえば |
| 言い換え | つまり |
| 前文を受けた操作 | これを受けて、この結果をもとに |

接続表現は、前後の事実関係に一致する場合だけ使う。
「そのため」「その後」のような表現は、因果や時間順を新しい事実として加えることがある。
根拠が因果や時間順を示していない場合は推測で補わず、対象名を繰り返すか、確認できた関係だけを書く。
同じ接続表現が続く場合は、語だけを置き換えず、文の役割や段落の分け方を見直す。
接続詞を増やすこと自体を目的にしない。

## 箇条書きを必要な箇所だけで使う

箇条書きは、並列関係、選択肢、手順、確認項目を示す場合に使う。
一つの項目には一つの役割を置き、同じ階層には同じ粒度の項目を並べる。

- 親項目には、読者が必ず読む内容または実行する内容を置く
  - 理由、例外、具体例は、対応する親項目の下へ置く
- 必須事項と補足を同じ階層へ混在させない
  - 優先度と読み順を判別できなくなるためである

文同士の因果や時間的なつながりを読ませる場合は、箇条書きへ分解せず段落で書く。
項目間で複数の条件を比較する場合は表を使う。
箇条書きの前後には、何を列挙し、読者がどう使うかを必要に応じて示す。

## 問いを近くで回収する

問いは、読者に比較、予測、確認を促す場合に使う。
答えは同じ節か、直後の例や結果で回収する。

前提条件、操作手順、安全規則、決定事項では、問いや含みを作らず直接書く。
見出しを疑問形にする場合も、その節で答えを示す。

## 各文で情報を増やす

各文が、読者の理解、判断、行動に必要な情報を増やしているか確認する。

残す文:

- 対象について新しい事実を示す
- 理由、条件、比較対象、結果の見方を示す
- 読者が行う判断または操作を示す
- 文書の範囲、読む順番、参照先を案内する

削るか書き換える文:

- 直前の内容を別の言葉で繰り返すだけの文
- 「重要なのは」「本質は」で始まり、条件や差分を示さない文
- 「詳しく見ていく」「掘り下げる」と進行だけを伝える文
- 見出しの内容を言い換えるだけの導入文
- 同じ注意や結論を前後で繰り返す文

案内文を一律に削除しない。
文書の範囲、現在地、次に読む箇所を特定する案内は残す。

## 否定文には理由か代替を添える

否定文は、禁止、制限、誤解の訂正に必要な場合だけ使う。
禁止や制限を書く場合は、同じ箇所で理由または代わりに行う操作を示す。

肯定文だけで必要な行動や条件が伝わる場合は、対比のためだけの否定文を追加しない。
肯定と否定で同じ内容を繰り返すと、確認条件が二つあるように見えるためである。

## 論理と事実の範囲を揃える

- 因果を書く場合は、その結果になる理由を示す
- 例が主張の一部しか支えない場合は、主張の範囲を狭める
- 複数の原因や判断を、一つの問題としてまとめない
- 推測、提案、確認済みの事実を区別する
- 「必ず」「すべて」を使う場合は、成立条件と例外を確認する
- 文書をまたいで、用語、分類、単位を揃える

根拠を確認できない事項は、「未確認」「可能性がある」「確認が必要」のように状態を明記する。
断定を弱めるだけで済ませず、確認方法が分かる場合は併記する。

## 読者の記憶負荷を減らす

- 後で使わない固有名詞、識別子、数値を並べない
- 初出の略語、専門用語、操作名を短く説明する
- 一つの用語に複数の意味を持たせない
- 新しい例を加える場合は、前の例との違いと追加理由を示す
- 手順では、開始位置、対象、操作、結果の見方を示す
- 例外は、対応する原則または手順の近くへ置く

前の節を読み返さないと理解できない文が続く場合は、必要な条件を現在の節へ短く置くか、参照先を明示する。

## 評価語を事実へ置き換える

次のような評価語を、理由や比較条件なしで使わない。

- 強い
- 刺さる
- 本質的
- 解像度が高い
- 重要
- 不可欠
- 核心的
- 包括的
- 効果的
- 簡単
- 柔軟

たとえば「この確認は重要です」ではなく、「この確認を省くと、別の環境の設定値を報告する可能性があります」と書く。
「簡単です」ではなく、必要な操作数、前提、所要時間など、読者が難易度を判断できる情報を示す。

## 過剰な演出を避ける

- 劇的な転回、決め台詞、体言止めを繰り返さない
- 書き手の逡巡や告白を導入にしない
- 読者の反応を想像して「そう思ったかもしれない」と演じない
- 不安を煽るために事故や危険を列挙しない
- 比喩だけで仕組みを説明しない
- 読者を褒めたり急かしたりして、内容の不足を埋めない

比喩を使う場合は、比喩のあとに実際の対象、条件、挙動を示す。

## 推敲手順

1. 文書の読者、利用場面、読後の判断または操作を一文で言えるか確認する
2. 見出しだけを読み、情報の場所と順序を確認する
3. 各段落を事実、理由、判断、指示、例、補足に分類する
4. 一つの段落に無関係な役割が混在していれば分ける
5. 表、コード、引用を除き、読点が3個以上ある文を抽出して読点の役割を確認する
6. 文頭の接続表現を一度外し、主語、述語、条件だけで関係を一通りに読める場合は削除する
7. 接続表現が必要に見える箇所でも、主語、述語、条件の明記で関係を示せないか先に確認する
8. 残した接続表現が前後の関係と一致し、同じ表現を機械的に繰り返していないか確認する
9. 抽象的な評価語を検索し、条件、理由、比較対象へ置き換える
10. 指示語と省略された主語を確認し、参照先が曖昧なら対象名を書く
11. 問いと前方参照を列挙し、近くで回収されているか確認する
12. 同じ定義、注意、結論、案内の重複を削る
13. 箇条書きの各階層で、項目の役割と粒度を揃える
14. 箇条書きが続く箇所を、段落や表へ戻した方が関係を理解しやすいか確認する
15. 否定文ごとに、理由または代替となる行動が近くにあるか確認する
16. 例が主張全体を支えているか確認し、支えない場合は主張を狭める
17. パス、リンク、コマンド、数値、固有名詞を根拠と照合する
18. 冒頭から読み直し、同じ長さと構文の文が不自然に続く箇所を直す
