# 読みやすい日本語文書を書く

読者が必要な情報を見つけ、内容を判断し、次の行動へ移れる日本語文書を作る。
文章を飾ることより、情報の順序、具体性、根拠、文と段落の変化を整える。

## 依頼の範囲を決める

依頼を次のいずれかに分類する。

- 新しい文書を作る
- 既存文書へ内容を追加する
- 指定された文書を改訂する

「説明を追加する」という依頼でも、新規ファイルを前提にしない。
同じ読者、利用場面、内容を扱う既存の節があれば、その箇所を改訂する。
新規ファイルは、既存文書と役割または読む時点が異なり、分けないと情報を探しにくくなる場合に作る。

「短く」「概要だけ」「手順だけ」などの指定は、内容上の制約として扱う。
指定された分量に必要事項が収まらない場合は、黙って長くせず、扱う範囲を絞る案を示す。

次の事項は、依頼または既存資料から確定できる場合だけ決める。

- 想定読者と前提知識
- 文書を読む場面
- 読後に読者が行う判断または操作
- 必須事項と補足事項
- 公開範囲、秘密情報、安全上の制約
- 文体、用語、分量、ファイル形式

選択によって内容が大きく変わり、既存資料からも確定できない場合は、推測で埋めずユーザーへ確認する。

## 根拠と既存文書を読む

執筆前に、依頼の範囲で次を確認する。

1. 対象文書の全体
2. 対象文書から直接参照される文書
3. 同じ読者や主題を扱う隣接文書
4. 用語、構成、文体、リンク表記を定めるリポジトリ内の規則
5. 記述する事実の根拠となるコード、設定、仕様、記録
6. [日本語文書の執筆規範](references/japanese-writing-rules.md)

既存の見出し、用語、表記、情報の置き場所を記録する。
内容を追加する前に中心語を検索し、同じ説明を別の場所へ複製しない。
詳細は一箇所に置き、ほかの文書から参照する。

## 読者と用途から構成を決める

本文を書く前に、次を短く整理する。

- 誰が、いつ読むか
- 読者が知りたいことは何か
- 読者が読後に判断または実行することは何か
- その判断や操作に必要な事実、条件、根拠は何か
- 読者が既に知っていることは何か
- 文書に含めない範囲はどこか

文書の主な役割に応じて、情報を次の順に置く。

- 解説：具体例、意味、仕組み、適用条件、例外
- 操作ガイド：目的、開始条件、手順、結果の見方、失敗時の対応
- 仕様・参照資料：対象範囲、定義、規則、入出力、制約、例
- 設計・意思決定記録：背景、判断対象、選択肢、比較条件、決定、影響
- 報告書：対象期間または範囲、確認した事実、分析、判断、残件
- 提案書：現状、解決する問題、提案、根拠、影響、判断が必要な事項

既存文書に構成がある場合は、機械的に上の順序へ置き換えない。
不足している役割だけを補い、読者が上から読んだときに疑問を近くで解消できるよう並べる。

## 本文を書く

[日本語文書の執筆規範](references/japanese-writing-rules.md)を全文に適用する。

先に内容を揃え、次に文章を整える。

1. 見出しごとに伝える事実、判断、操作を置く
2. 事実と推測、決定と提案、必須事項と補足を分ける
3. 具体例のあとに、その例から読み取れる範囲だけを説明する
4. 操作を書く場合は、開始位置、対象、結果の見方を含める
5. 段落、箇条書き、表を情報の関係に応じて使い分ける
6. 表、コード、引用を除き、読点が3個以上ある文を抽出して[読点の点検](references/japanese-writing-rules.md#読点を点検する)を行う
7. 文頭の接続表現を一度外し、同じ段落で隣り合う文の関係を[文同士の接続関係](references/japanese-writing-rules.md#文同士の接続関係を示す)に従って確認する
8. 規範の推敲手順で冗長さ、曖昧さ、単調さを直す

既存文書の語調は尊重するが、読みにくさまで再現しない。
既存表現と規範が競合する場合は、用語と事実関係を保ったまま、文と構造を読みやすくする。

## 事実を検証する

文書で断定する事実を、利用できる根拠と照合する。

- ファイル名、ディレクトリ名、相対リンク
- コマンドを実行する場所、引数、期待する結果
- 設定値、既定値、対応バージョン
- 画面の表示、操作順、権限
- 仕様、制約、用語の定義
- 決定事項、担当、期限、状態

コードの挙動やコマンド結果を断定する場合は、該当箇所を読むか、安全な方法で検証する。
確認できない事項は断定せず、未確認であることと確認方法を示す。
外部情報が必要な場合は、依頼と利用可能な手段の範囲で一次情報を確認する。

## 変更を点検する

執筆後、変更した範囲を次の順で確認する。

1. 読者、利用場面、読後の判断または操作が文書の内容と一致している
2. 見出しだけを読んでも、必要な情報の場所を予測できる
3. 結論、条件、根拠、例外の関係が分かる
4. 表、コード、引用を除き、読点が3個以上ある文をすべて点検している
5. 文頭の接続表現を外しても関係を一通りに読める箇所では、接続表現を使っていない
6. 接続表現を外すと関係を誤読する箇所では、主語や条件の明記を先に検討している
7. 残した接続表現が前後の事実関係と一致し、同じ表現や文型を機械的に繰り返していない
8. 初出用語を説明し、文書間で表記を揃えている
9. 同じ定義、注意、結論を複数箇所へ重複させていない
10. 箇条書きの各項目が同じ粒度と役割で並んでいる
11. 操作手順に開始位置、対象、成功時と失敗時の見方がある
12. リンク、パス、コマンド、数値、固有名詞を根拠と照合している
13. `TODO`、仮の値、未回収の問い、不要な進行実況が残っていない
14. [推敲手順](references/japanese-writing-rules.md#推敲手順)を実行している

文書を変更したリポジトリにMarkdown検査や文書検証の手順がある場合は、その手順を実行する。
専用の検査がない場合は、変更したファイルの差分とローカルリンクを確認する。

## 結果を報告する

次を簡潔に報告する。

- 作成または変更した文書
- 読者と用途に合わせて変えた構成
- 根拠と照合した事項
- 実行した検証と結果
- 未確認事項または人間の判断が必要な事項
